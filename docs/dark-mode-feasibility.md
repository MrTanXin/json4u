# 暗黑模式可行性评估

对应 [Issue #15](https://github.com/MrTanXin/json4u/issues/15)。

## 结论

可在现有依赖上实现全站暗黑模式。Next.js 根布局已接入 next-themes，站点有一部分暗色变量，Monaco 和 React Flow 也有内置暗色主题。主要工作是统一主题信号、补齐界面和比较区的颜色，并做跨主题和移动端回归。预计 **3–5 人日**，包含实现和首轮验收。

在本地 Chromium 中预置 `localStorage.theme=dark` 后，编辑器页面背景变为 `#020817`，Monaco 编辑区、图节点与差异标记仍呈浅色。调用 Monaco 的 `setTheme("vs-dark")` 后，编辑区背景变为 `#1E1E1E`，示例文本仍在。该探查验证了页面和 Monaco 各自已有的切换能力。下文的同步方式、配色和工时属于实施方案，完整交互需在实现后验收。

## 切换与持久化

- 提供「浅色」「深色」「跟随系统」三个选项。仅手动切换无法响应系统设置，仅跟随系统则无法为本站单独选色。两者兼容时，显式选择优先，只有选中「跟随系统」时才响应系统配色变化。首版默认保留浅色。
- 复用 next-themes 的 `setTheme` 和已有的 `localStorage.theme`，分别保存 `light`、`dark` 或 `system`。偏好在同源页面、刷新和重开后持续生效。清除站点存储后回到默认值，设备之间各自保存。
- 沿用根节点 `data-theme` 和 next-themes 的首屏初始化脚本，把 Tailwind 的 `dark:` 选择器对齐到该属性。主题控件挂载后再显示当前选择，为首屏保留同尺寸占位。桌面入口放在首页导航和编辑器侧栏，窄屏入口放在移动菜单或侧栏可点击区域，支持触屏和键盘。
- 组件通过 `resolvedTheme` 获得最终配色。把当前位于 Provider 外的 Sonner 移入其内部，使通知与页面同步。[next-themes 文档](https://github.com/pacocoursey/next-themes)

## 编辑器与差异标记

浅色使用 Monaco 的 `vs`，暗色使用 `vs-dark`，保留 Monaco 的系统高对比度检测。以同一个 `resolvedTheme` 更新左右编辑器，避免由于单个编辑器延迟挂载而改变全局配色。切换时保留两个模型、撤销历史、光标和滚动位置。[Monaco 主题选项](https://microsoft.github.io/monaco-editor/typedoc/interfaces/editor_editor_api.editor.IGlobalEditorOptions.html#theme)

比较区继续使用现有装饰类，按主题覆盖整行、行内、边栏和补齐行变量。以下为基于 `vs-dark` 背景 `#1E1E1E` 的候选实色，应用后以浏览器中的实际合成颜色复核。

| 位置     | 删除               | 新增               |
| -------- | ------------------ | ------------------ |
| 整行背景 | `#302126`          | `#202D27`          |
| 行内背景 | `#3C252C`          | `#213129`          |
| 边栏标记 | `#FF8182`，带「−」 | `#56D364`，带「+」 |

对齐补齐行用中性色 `#292D32`。删除与新增同时利用形状或符号表达，配上可读的名称，并检查当前行、搜索匹配、选区和错误叠加时的可读性。验收目标是普通文本对比度至少 4.5:1，传递必要信息的非文本标记至少 3:1。行底色保持低干扰，可辨识性由边栏标记与文字承担。[WCAG 文本对比度](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html) · [非文本对比度](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html) · [颜色使用](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html)

## 风险与验收

- **首屏与跨组件同步**。分别在系统深色、系统浅色及站点手动反选的组合下检查刷新和导航。确认首页、教程、左右编辑器、图表、搜索、弹层与通知同步，且主题控件无 hydration 警告。
- **编辑行为与性能**。主题切换预计只触发重绘及相关组件更新。验收时用大 JSON 对比切换前后的耗时，确认不会重建 Monaco 模型、重启 Worker 或再次触发解析和比较。回归查找替换、导入导出、语法错误、图表和两种比较模式。
- **窄屏与可访问性**。用 390 px 窄屏和桌面检查菜单入口、焦点、选中态、触摸滚动和分栏。结合 Chromium、Firefox 和 WebKit 复核持久化、实时系统切换及对比色，覆盖系统高对比度。

后续按「主题与公共变量 → Monaco 和比较装饰 → 图表、首页与教程 → 跨浏览器验收」推进。在文字与差异标记验收通过后再开放暗色选项。
